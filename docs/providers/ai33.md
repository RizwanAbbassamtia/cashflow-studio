# ai33 (OpenSpeaker) voice adapter

`backend/cashcow_studio/providers/voice/ai33.py`, catalogue entry `voice.ai33` in
`config/providers.yaml`, selected by `CCS_VOICE_PROVIDER=ai33` or, when no app-wide provider
is set, by a channel whose Voice tab picks **ai33 (OpenSpeaker)** (the Settings voice row
then says so). Only ai33 is picked up from the channel this way: MiniMax and Cartesia run
only when `CCS_VOICE_PROVIDER` names them. Tests: `tests/test_voice_ai33.py` (httpx
MockTransport, no network).

Written against the public part of <https://ai33.pro/app/api-document>, read as a guest on
2026-10-10. The **Common** tab (task status), the **Elevenlabs** and **Imagen** tabs were not
readable without a login. Everything under "To confirm after login" below is a guess that the
adapter tolerates, not a fact.

## What is known (guest view of the API document)

| Item | Value |
| --- | --- |
| Base URL | `https://api.ai33.pro` |
| Auth | header `xi-api-key: <API_KEY>` on every call; keys need a paid ai33 plan |
| Synthesis | `POST /v3/text-to-speech`, multipart form: `text` (max 1,000,000 chars), `voice_id`, `speed` (0.5-1.5, default 1), `with_transcript` (bool), `file_name`, `receive_url` (webhook), `pronunciation_dictionary_id` |
| Synthesis answer | `{"success": true, "task_id": "<uuid>"}`; the result is pushed to the webhook or fetched by polling "Common / GET Task" |
| Voice ids | prefixed by engine: `elevenlabs_`, `minimax_`, `clone_`, `edge_`, `kokoro_`, `vbee_`, `fishaudio_` |
| Voices | `GET /v3/voices?provider=<engine>&language=..&gender=..&search=..&page=1&page_size=30` (max 100); answer `{"success", "format_version": "2026-05-29", "data": [{voice_id, name, language, gender, tags, preview_url}], "pagination": {page, page_size, total, has_more}}` |
| Cloning | `POST /v3/text-to-speech/voice-clone` multipart `voice_name` + `audio_file` (<= 10 MB) -> `{"success": true, "data": {"voice_id": "123"}}`; use as `clone_123`; `DELETE /v3/text-to-speech/voice-clone/{id}` |
| Dictionaries | `POST/GET/PUT/DELETE /v3/dictionaries[/:id]`, `POST /v3/dictionaries/preview` (not used by the app yet) |
| Dialogue | `POST /v3/text-to-speech/dialogue` (multi-speaker; not used) |
| Billing | credits; the app reports every sentence as 0 USD with the note "Billed in ai33 credits" |

## How the adapter behaves

**Synthesis (`synthesize`)** - one sentence per request, as every voice adapter in this app:

1. `POST /v3/text-to-speech` as multipart with `text`, `voice_id`, `speed` clamped to 0.5-1.5,
   `with_transcript=true` and `file_name` = `ccs-<first 24 chars of the sentence cache key>`
   (the request's idempotency key).
2. The voice id from the channel (`voice.clone_ref`) is normalised: `123` -> `clone_123`
   (prefix from `options.default_voice_prefix`), an id that already carries an engine prefix is
   kept, a pasted link keeps its last path segment.
3. If the answer itself is audio (`Content-Type: audio/*`) it is used directly. Otherwise the
   JSON is read: `success: false` is a refusal with the server's message; an audio link in the
   answer means no polling (unless its status says the task is still running); else the
   `task_id` is polled. `{"success": true, "status": "success", "task_id": ...}` counts as
   accepted, not as finished.
4. Polling. Until a status path is known, every path in `options.poll_paths` is asked in turn
   and the first one whose answer is **about the task** is remembered for every later
   sentence: the answer repeats the task id (`task_id`, `id`, `uuid`, ...), carries a known
   status word, or links to an audio file. `{"message": "Cannot GET ..."}`, `{"data": null}`,
   `[]` or `{"success": false, "message": ...}` are not about the task, so a path that sends
   them is never remembered. A new task may not be visible at once, so the paths are asked up
   to 4 times (with the normal waits) before "endpoint not found". One path refusing the key
   (401/403, e.g. a web route that wants a login) only rules that path out, because the POST
   was just accepted with the same key; every path refusing stops at once.
   The remembered path is kept until the app restarts. If it gives 4 answers in a row that
   say nothing about the task (a 404, a message without a status), it is forgotten and the
   paths are asked again; if it had already reported this task, the sentence stops with the
   server's words instead ("ai33 stopped reporting on this sentence").
   Interval 1.5 s growing by half each time up to 5 s (`poll_interval_s`,
   `poll_max_interval_s`, at most 60 s); timeout 180 s (`poll_timeout_s`, at most 3600 s; a
   value that is not a number, or `.inf`, falls back to the default).
   A submitted task is paid for, so passing trouble while polling (a network error, a 5xx, a
   429 after its `Retry-After`) counts as "still running"; 5 in a row stop the sentence with
   the last error. A 401/403/402, or a refusal that names the key or the credits, from the
   confirmed path stops at once.
   Status words `pending/processing/queued/running/...` (and unknown words) keep polling,
   even when the answer already names the link where the audio will be; `failed/fail/error/
   rejected/expired/...` raise with the server message; a finished word (`completed/success/
   done/finished`) without an audio link is an error. When an envelope and the task both carry
   a status (`{"status": "success", "data": {"status": "processing"}}`), a failure word wins
   over a running word, which wins over a finished one.
   The audio link is any of `audio_url`, `url`, `file_url`, `output_url`,
   `result.audio_url`, `data.audio_url`, else the first string in the document that is an
   http(s) link ending in `.mp3/.wav/.m4a/.ogg` or containing "audio" (keys that name
   something else, such as `preview_url`, transcripts or help links, are skipped).
5. The audio is downloaded with the key header **only when the link is on the API host**;
   a storage or CDN host gets a bare request (also after a redirect). A passing failure of
   the download (network, 5xx, 429) is tried again, 3 attempts in all. FFmpeg converts it to
   48 kHz mono 16-bit WAV; a file without any sound is refused (it would be cached silent).
6. Transcript: a link (`transcript_url`, `srt_url`, `subtitle_url`, ...) or inline value
   (`transcript`, `srt`, `subtitles`, `words`, `segments`) is parsed as SRT/WebVTT or JSON.
   Per-word times (`words: [{text|word, start, end}]`, also inside `segments`) become word
   rows with `source=provider` (timing.json says `provider_word`); sentence cues are cut into
   words by character length with `source=estimated` (timing.json says `provider_sentence`).
   Milliseconds are detected against the audio length (without one, a time over 600, ten
   minutes, is taken as milliseconds). Nothing parseable -> no words, the stage estimates.
   Timing problems never fail a sentence (they are logged).

**Voices (`list_voices(language=None)`)** - pages through `GET /v3/voices` for each engine in
`options.voice_providers` (default `clone, elevenlabs, minimax, fishaudio, vbee`), 100 per
page, until `has_more` is false or 10 pages; cached in memory for 10 minutes. `language` is
passed to the API as typed (ai33 uses tags such as `vi-VN`).

**Cloning (`create_clone`)** - refused without a consent record (owner and recorder filled
in). The first sample is uploaded as it is when it is an MP3 or WAV under 10 MB, otherwise
FFmpeg converts it to a mono 96 kbps MP3 first (over 10 MB even then -> plain error). Returns
`clone_<voice_id>`.

**Health** - local facts only, like every adapter, so the Settings and Doctor pages never
wait on ai33: without a key "Add your ai33 API key in Settings"; with a key "Key set (ai33
checks it with the first sentence)". Nothing is called at import, at app start or when a
page loads. `check_key()` is the explicit network check: `GET
/v3/voices?provider=minimax&page_size=1` (5 s timeout) -> `ok`, `fail` (key rejected) or
`warn` (ai33 unreachable), cached for a minute per key and shared by every adapter instance
(the Settings page builds new ones on each load). `options.health_probe: true` makes
`health()`, and so the Settings page, use that check; it is off by default. No button calls
`check_key()` yet.

**Errors** are plain English and never carry the key. The key value is removed from every
text ai33 sends back (HTTP error bodies, `{"success": false, "message": ...}` answers with
HTTP 200, failed-task reasons) before the text is cut to length and reaches an exception, a
log line or a health detail; a last guard on every public call checks the final message and
the exceptions it was raised from, and the registry scrubs every health detail again.
Messages: missing key, 401/403 ("ai33 rejected the key"), 402 (no credits left), 429 (rate
limit, with the Retry-After seconds), unknown task endpoint ("ai33 task status endpoint not
found: none of the status paths in config/providers.yaml (voice > ai33 > options >
poll_paths) answered ... Last answers: <path>: <what it answered>; ..."), task failed (server
message), task no longer reported ("ai33 stopped reporting on this sentence (task ...):
<server message>"), timeout ("did not finish this sentence within 180 seconds ... raise
poll_timeout_s", only when the task was seen running; otherwise the last error or "gave no
usable answer about this sentence"), audio without sound.

**Capabilities** - languages: the plan's top ten plus Vietnamese; `timestamp_granularity`
starts at `sentence` and switches to `word` once a transcript with word times was parsed;
`max_chars` 1,000,000 (the app still sends one sentence per request); `billing_unit: credit`.

## To confirm after login (assumptions the adapter makes)

1. **Task status endpoint.** Unknown path. Candidates tried in order:
   `/v3/tasks/{task_id}`, `/v3/task/{task_id}`, `/v3/common/task/{task_id}`,
   `/v3/common/tasks/{task_id}`, `/common/task?task_id={task_id}`. Open the **Common** tab of
   the API document while logged in, read the real path and put it **first** in
   `options.poll_paths` (or make it the only entry), then restart the app: the adapter reads
   the list when it is built and keeps the path that worked until the app restarts (or until
   that path stops answering about tasks). A path with `{task_id}` is filled in; a path
   without it gets `/<task_id>` appended; a full `https://...` URL is used as given (and gets
   the key header, whatever its host).
2. **Task JSON shape.** Assumed fields: a status word under `status` / `data.status` /
   `result.status` / `state`; an audio link under one of the names listed above; an error text
   under `error` / `message` / `detail`. A status answer only counts when it is about the task
   (step 4 above): if the real answer has none of the known status words, repeats no task id
   under `task_id` / `id` / `uuid` and has no audio link yet, the path is not recognised and
   the "endpoint not found" message lists what it answered. If the real answer uses other
   names or words, add them to the constants at the top of `ai33.py` (`STATUS_FIELDS`,
   `PENDING_STATUSES`, `DONE_STATUSES`, `FAILED_STATUSES`, `TASK_ID_KEYS`,
   `AUDIO_URL_FIELDS`, `ERROR_FIELDS`).
3. **Transcript delivery and shape** when `with_transcript=true`: a link or inline text, SRT or
   JSON, with or without per-word times. The parsers accept all of these; which one ai33 uses,
   and whether word times exist per engine, is unknown. Until then the channel's
   "Gives word timings?" stays unknown (`null`).
4. **Audio host and format.** Assumed an MP3 or WAV on a storage host that needs no key
   (presigned link). If the link is on `api.ai33.pro`, the key header is sent.
5. **Direct audio answers** (body = the file) are supported but undocumented.
6. **Voice-clone sample formats.** Only "audio_file <= 10 MB" is documented; MP3 and WAV are
   assumed accepted.
7. **Rate limits and credit errors.** 402/429 handling is defensive; the real codes and the
   credits-per-character rate are unknown, so costs are reported as 0 USD.
8. **Language filter values** for `GET /v3/voices` (`vi-VN` style tags seen in a sample row).
9. **Webhooks** (`receive_url`) are not used: the desktop app has no public address.
10. **Elevenlabs tab.** Not readable as a guest. Check whether it offers synthesis that
    returns timestamps (that would give word times directly, instead of whatever
    `with_transcript` gives) and whether its voice ids match the `elevenlabs_` ids of
    `GET /v3/voices`. The adapter uses only the v3 endpoints above.
11. **Imagen tab (images).** Not readable as a guest, and nothing in the app uses it: the
    image stage calls Google Gemini directly (`providers/image/gemini.py`, `GEMINI_API_KEY`).
    Before ai33 could make scene images or thumbnails, confirm the endpoint, the models,
    sizes and aspect ratios, reference-image support, credits per image, and whether results
    come back directly or through the same task polling as speech. Such an adapter would be a
    new `providers/image/ai33.py` with its own entry under `image:` in `config/providers.yaml`.

## Setup for a channel

1. Settings > API keys: add `AI33_API_KEY` (saved in `<app_data_dir>/.env`).
2. Channel Setup > Voice: tool **ai33 (OpenSpeaker)**, clone link or voice id `clone_<id>` (the
   id shown in the ai33 web app after cloning) or a stock voice id such as `minimax_<id>`,
   key name `AI33_API_KEY`, and the consent record for a clone.
3. First run: watch the log for `ai33 task status endpoint: <path>`; if the voice stage stops
   with "ai33 task status endpoint not found" (the message lists what each path answered),
   fix `options.poll_paths` as described above and restart the app.

The voice step's consent check (policy `voice.consent`) counts any filled-in voice id as a
clone, so for now a stock voice id such as `minimax_<id>` also needs the Consent fields.
